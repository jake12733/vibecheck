AI가 자주 만드는 innerHTML · dangerouslySetInnerHTML
XSS 취약점 안전한 해결 가이드

AI 코딩 도구는 UI를 빠르게 조립하기 위해 템플릿 리터럴과 element.innerHTML = ...를 즐겨 사용합니다. 이때 사용자 이름, 검색어, URL 파라미터가 이스케이프 없이 들어가면 방문자의 브라우저에서 임의의 악성 자바스크립트가 실행되는 XSS 공격이 성립합니다.

UPDATED 2026-11-25READ TIME: 3 MINXSS · DOMPURIFY · TEXTCONTENT

1. 위험한 패턴 vs 안전한 패턴

단순 텍스트를 출력할 때는 절대로 innerHTML을 쓰지 말고 textContent를 사용하세요.

// ❌ 위험: 사용자가 <img src=x onerror=alert(1)> 입력 시 스크립트 실행
titleEl.innerHTML = `환영합니다, ${userName}님`;

// ✅ 안전: HTML 태그를 일반 문자열로만 렌더링
titleEl.textContent = `환영합니다, ${userName}님`;

2. HTML 렌더링이 꼭 필요할 때: DOMPurify 적용

마크다운 미리보기나 리치 텍스트 에디터처럼 HTML 태그 자체가 필요한 경우에는 반드시 검증된 새니타이저인 DOMPurify를 통과시켜야 합니다.

import DOMPurify from 'dompurify';

// ✅ 위험한 <script>, onerror, javascript: URL 자동 제거
const cleanHtml = DOMPurify.sanitize(rawMarkdownHtml);
previewEl.innerHTML = cleanHtml;

3. React에서 dangerouslySetInnerHTML 안전하게 쓰기

<div
  dangerouslySetInnerHTML={{
    __html: DOMPurify.sanitize(article.htmlContent),
  }}
/>

4. eval() / new Function() 제거

수식 계산기나 JSON 파싱에서 AI가 가끔 eval(input)을 생성합니다. eval은 사실상 원격 코드 실행 구멍이므로 반드시 JSON.parse() 또는 안전한 수식 파서 라이브러리로 교체하세요.
