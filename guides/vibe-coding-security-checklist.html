PRE-LAUNCH CHECKLIST · 바이브코딩 보안

바이브코딩 배포 전 필수 보안 체크리스트 10가지
(Cursor · Claude · Bolt · Lovable 공통)

AI 코딩 도구는 "지금 당장 화면이 잘 돌아가게 만드는 것"에 최적화되어 있습니다. 그 때문에 실제 서비스 운영에서 치명적인 보안 장치를 생략하는 패턴이 반복됩니다. 출시 직전 아래 10가지만 점검해도 사고의 95%를 예방할 수 있습니다.

UPDATED 2026-11-25READ TIME: 5 MINVIBE-CODING SECURITY AUDIT

1. 클라이언트 번들에 서버용 비밀키가 들어있지 않은가?

NEXT_PUBLIC_이나 VITE_ 접두사가 붙은 환경변수는 브라우저에 그대로 노출됩니다. DB 관리자 키, OpenAI/Anthropic 키, Stripe Secret Key는 절대로 프론트엔드 코드에 넣지 마세요.

2. Supabase RLS / Firebase 보안 규칙이 켜져 있는가?

AI가 초안을 짤 때 빠른 테스트를 위해 allow read, write: if true; 또는 RLS 비활성화 상태로 두는 경우가 가장 많습니다. 배포 전 반드시 본인 데이터(auth.uid() = user_id)만 접근 가능하도록 잠가야 합니다.

3. API 엔드포인트에 서버 측 권한 검증이 있는가?

프론트엔드에서 버튼만 숨기는 것은 보안이 아닙니다. 관리자 삭제·결제 승인·유료 기능 호출 API는 서버 핸들러에서 반드시 세션 토큰과 역할을 재검증하세요.

4. AI 호출 API에 Rate Limit(요청 제한)을 걸었는가?

무료 체험 AI 엔드포인트에 IP/사용자당 횟수 제한이 없으면 악성 봇 1대가 하룻밤 사이에 수백만 원의 LLM 토큰 요금을 발생시킬 수 있습니다. Cloudflare Rate Limiting 또는 Upstash Redis로 분당 요청을 제한하세요.

5. innerHTML / dangerouslySetInnerHTML XSS 점검

마크다운 렌더링이나 사용자 댓글 출력에 innerHTML을 직접 썼다면 DOMPurify.sanitize()로 감싸거나 textContent로 교체하세요.

6. CORS 설정이 와일드카드(*) + 인증쿠키 조합이 아닌가?

프로덕션 API에서는 허용 도메인(Access-Control-Allow-Origin)을 본인 서비스 도메인으로 명시적으로 제한하세요.

7. 결제 금액을 클라이언트가 아닌 서버에서 계산하는가?

프론트엔드에서 { price: 100 }을 보내고 서버가 그대로 결제 승인하면 100원 조작 공격에 취약합니다. 서버가 상품 ID로 DB 원가를 조회해 결제 금액을 확정해야 합니다.

8. .env 및 개인키가 .gitignore에 포함되어 있는가?

.env*, *.pem, node_modules/가 .gitignore에 누락되면 다음 커밋에서 사고가 발생합니다.

9. 외부 새 탭 링크에 rel="noopener noreferrer" 적용

target="_blank" 링크에는 반드시 rel="noopener noreferrer"를 붙여 탭내빙(Tabnabbing)을 차단하세요.

10. SEO 메타태그 & 에러 페이지(404/500) 정비

프로덕션에서 서버 스택 트레이스(DB 구조·파일 경로)가 사용자 화면에 그대로 노출되지 않도록 일반화된 에러 메시지를 반환하고, title·description·OpenGraph 태그를 완성하세요.
