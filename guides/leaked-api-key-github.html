GitHub에 API 키·.env를 실수로 올렸을 때
5분 만에 복구하는 정확한 순서

GitHub 공개(Public) 저장소에 OpenAI(sk-), AWS(AKIA), Stripe(sk_live_) 키를 푸시하면 평균 10~30초 이내에 자동화 크롤링 봇이 키를 수집해 무단 과금을 일으킵니다. 단순히 파일만 지우고 다시 커밋해서는 절대 안전하지 않습니다.

UPDATED 2026-11-25READ TIME: 4 MINKR / EN KEYWORDS: GITHUB LEAKED API KEY FIX
가장 먼저 할 일 (Step 0): Git 정리보다 "키 폐기(Revoke)"가 1순위입니다!

이미 공개 저장소에 1초라도 올라간 키는 유출된 것으로 간주해야 합니다. Git 히스토리를 지우는 동안에도 봇은 이미 훔쳐간 키로 결제 요청을 보낼 수 있습니다. 반드시 서비스 콘솔에서 기존 키를 먼저 삭제(Revoke)하고 새 키를 재발급하세요.

1단계: 주요 플랫폼별 1분 키 폐기 체크리스트

  • OpenAI / Anthropic: API Keys 콘솔 → 유출된 sk-... 키 즉시 Delete → Usage Limit(월 상한) 설정 후 새 키 발급
  • AWS: IAM → Users → Security Credentials → 노출된 AKIA... 액세스 키 Deactivate & Delete → CloudTrail에서 무단 EC2 생성 여부 확인
  • Stripe: Developers → API Keys → sk_live_... Roll Key 즉시 실행
  • GitHub Token: Settings → Developer Settings → Personal Access Tokens → Revoke
  • Firebase / Google API Key: 클라이언트용 AIza... 키는 공개되어도 정상인 경우가 있으나, 반드시 Google Cloud Console에서 HTTP 리퍼러(내 도메인) 제한과 API 사용 범위 제한을 걸어야 과금 폭탄을 막을 수 있습니다.

2단계: .gitignore에 .env 추가 후 추적 해제

앞으로 실수가 재발하지 않도록 루트 경로의 .gitignore에 환경변수 파일을 반드시 등록합니다.

# .gitignore
.env
.env.local
.env.*.local
.env.production
*.pem
*.key
firebase-adminsdk*.json

이미 커밋된 .env를 내 PC에서는 유지하면서 Git 추적만 끊으려면 아래 명령을 실행합니다.

git rm --cached .env
git add .gitignore
git commit -m "chore: stop tracking .env and add to gitignore"
git push

3단계: 과거 Git 커밋 히스토리에서 파일 완전 소거

git rm --cached만 실행하면 이전 커밋 로그를 클릭했을 때 여전히 .env 내용이 보입니다. 과거 기록까지 깨끗이 지우려면 공식 권장 도구인 git-filter-repo를 사용하세요.

# 1) git-filter-repo 설치 (Python pip)
pip install git-filter-repo

# 2) 전체 커밋 히스토리에서 .env 파일 완전 제거
git filter-repo --invert-paths --path .env --force

# 3) 원격 저장소 강제 덮어쓰기 (팀 프로젝트는 사전 공유 필수)
git push origin --force --all
git push origin --force --tags

4단계: 프론트엔드 정적 사이트에서 API 키를 숨기는 정석 구조

바이브코딩으로 만든 HTML/React/Vite 앱에서 VITE_OPENAI_API_KEY처럼 브라우저 번들에 키를 넣으면 개발자 도구(F12)에서 누구나 볼 수 있습니다. 비밀키가 필요한 호출은 반드시 Cloudflare Workers, Vercel Serverless Functions, Supabase Edge Functions 같은 무료 서버리스 프록시를 거쳐 호출하세요.
